先讲一道国企上 AI 时几乎必做的选择题，调云端 API，还是本地自己跑。调云端 API 看着省事，接口一对接就能用，不用自己操心算力。可省事的背后藏着三笔账。第一笔是数据账，你每问一次，数据就要往外发一次，对很多单位来说这本身就过不了安全这一关。第二笔是成本账，云端按调用量计费，平时不显，量一上来就肉疼，用得越多花得越多，长期看是个无底洞。第三笔是合规账，涉密场景、物理隔离的内网，根本就不让你连外网，云端 API 这条路从一开始就走不通。这三笔账叠在一起，很多国企对着这道选择题，左右为难。

我们把这个痛点想透。国企对 AI 的诉求，和一般用户不太一样。一般用户图的是好用就行，国企还得同时算安全账和成本账。安全账要求数据别往外跑，最好物理隔离也能用；成本账要求别被按次计费拖成长期负担，量大也扛得住；再叠上自主可控的要求，最好还能用上国产模型。云端 API 在这三条上几乎条条踩雷，可不用 AI 又跟不上提效的需要。这道题的本质是，国企需要的是一条既智能、又安全、还省钱的路，而不是在省事和安全之间被迫二选一。

察元 AI 给的就是另一条路，把推理放到本地来。它有一个模型广场，你可以在里面把本地模型、国产模型一键挂上，对话、embedding、rerank 这些都在你自己的机器上完成，不往外发。它支持 Ollama 这类本地推理，本地模型挂进来就能跑。这意味着，AI 的核心计算搬到了你的机器、你的内网里，数据原地不动，不出域；不按调用次数收费，用多少是自己的算力；断网也照样能用，物理隔离的环境也能落地。智能、安全、省钱，这条路把三笔账一起算平了。

我顺着一条真实的部署思路给你讲。先在模型广场里把要用的本地模型、国产模型挂上，对话就用本地的模型来跑。要建知识库做检索，embedding 和 rerank 也都放在本地完成，整条检索链路不出机器。担心机器老、配置不够？察元考虑到了，老电脑也别怕，可以用 sqlite-vec 做本地索引，照样跑得动，不是非得高配服务器才能用。这样一来，从对话到检索到索引，全套在本地闭环，数据不出域、不按次收费、断网能用，正好对上国企的安全账和成本账。

跟云端 API 比，差别非常实在。云端是数据上行、按次计费、依赖外网，安全、成本、合规三头都受制于人。察元的本地推理是数据原地、算力自有、断网可跑，主动权全在自己手里。再说自主可控这一层，云端 API 用的往往是人家的模型、人家的接口；察元让你在模型广场里挂本地和国产模型，想用哪个挂哪个，推理算力实实在在攥在自己手上。对国企来说，这不只是省了钱，更是把 AI 的根基立在了自己的机器上。

落到操作上不复杂。察元是桌面单机版，装到机器上，后端本地起服务，端口是 62581。打开模型广场，把本地模型、国产模型挂上，配好对话、embedding、rerank 用本地引擎。老机器就开 sqlite-vec 做本地索引。数据目录由 CHAYUAN_ROOT 指定，落在你自选位置，知识库就在这个目录下的 data 文件夹里。装完断网，先用本地模型试出第一句对话，确认这套东西真的能在本地独立跑。

可能有人担心，本地跑会不会很折腾、维护成本高。但比起云端那三笔长期账，本地这点配置是一次性的，而且省下的是持续的调用费和数据风险。再加上它免费开源，协议 AGPL-3.0，源码在 GitHub 上可审，本地推理是不是真的不外发，技术人员可以自己抓包核对，踏实。
