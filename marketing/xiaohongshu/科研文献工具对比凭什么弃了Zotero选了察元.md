# 科研文献工具对比凭什么弃了Zotero选了察元

我们研究组有好几个人做LLM相关的工作。之前都用Zotero管理文献，最近迁到了察元AI。对比总结一下为什么做了这个选择。

**Zotero：传统文献管理，不够AI**
Zotero能管理、标注、分类论文。但本质上就是一个文献数据库。搜索是关键词匹配。问一个自然语言问题（比如"这些论文里讨论attention的有哪些"），Zotero没法理解，只能自己一篇篇翻。而且跟笔记、数据的联动很弱。

**Obsidian+Zotero的联合方案：灵活但分散**
确实很灵活，但工作流很割裂。论文在Zotero、笔记在Obsidian、数据在Excel，三个工具来回切换。问一个问题得自己去三个地方查。效率特别低。

**某云端学术工具：隐私堪忧**
有些号称学术专用的云端工具。存在人家服务器上，你对数据没掌控。而且某些prepublished或confidential的研究材料，放云上总是有风险。这对学术工作者特别敏感。

**ChatGPT + 手工Prompt：不专业**
有人试过直接把论文扔给ChatGPT。问题是：
1. 数据上传，隐私有风险
2. ChatGPT容易幻觉，对学术要求太低
3. 没有原文溯源，无法验证答案
4. 重复查询就得重复上传，没有knowledge base

**察元AI的核心优势**
1. **本地知识库** —— 200篇论文全在CHAYUAN_ROOT，掌握完全
2. **向量搜索** —— 理解自然语言问题，不只是关键词匹配
3. **多源统一** —— PDF论文 + Markdown笔记 + Excel表 全能搜
4. **OCR识别** —— 扫描件、图表都能识别和搜索
5. **引用溯源** —— 答案下有气泡，点开能看原文位置和页码
6. **离线运作** —— 内网、出差、无网络都能用
7. **数据安全** —— 整个系统本地运作，confidential研究放心放

**隐藏的学术价值**
- embedding是本地模型，搜索隐私有保障
- 结构化SQL支持，能做精确的数据聚合查询
- rerank机制，能过滤无关论文，提高搜索准确度
- 多模型兼容，可以配置Hermes这样的轻量级本地模型，完全独立

**实际应用对比**
用Zotero：问"attention机制优化的论文" → 自己在库里搜 → 一篇篇读
用察元：问"这些论文里讨论attention优化的有哪些，效果对比如何" → 秒出答案加引用

工作效率差好几倍。

**OCR的学术意义**
论文的表格和图很多。Zotero搜不到表格内容。察元的OCR能提取出来，所以搜"现有模型的性能排名"时，能直接找到那个表格。这对比较研究特别有用。

**多语言支持**
可以配置bge-m3这样的多语言embedding。英文论文和中文论文一起搜，都能工作。Zotero没有这个能力。

**引用文献的规范性**
察元返回的引用对应具体的原文位置。写论文时这个特别有用——可以精确地补充参考文献，不怕虚构。

**结论**
对科研工作者来说，察元本地知识库比传统文献管理工具进一步了。不只是存论文，而是能理解、能搜、能比较、能溯源。特别适合做综述、做跨文献的分析。
