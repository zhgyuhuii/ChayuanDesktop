# 老旧办公电脑生成视频的四款工具对比测评

我在同一台5年前的老电脑（i5核显8GB内存）上装了四个视频生成工具：Runway、CapCut、本地llama.cpp+ffmpeg、察元AI。结论出人意料。

Runway是业界标准（文生视频、图转动画都一级棒）。但这台老电脑装了Runway就彻底卡了——它需要24GB显存才能跑完整模型，核显内存不足，自动fallback到云端。这样的话，网要特别好，不然就是无限转圈。对我这种内网电脑完全无用。

CapCut是最轻的（剪视频、配字幕、简单特效）。这台老电脑装了跑得很流畅。但生成视频的功能特别阉割——没有文生视频、没有AI配音、AI功能几乎都是在线的。单纯用来手工剪现成视频还行，作为"生成工具"很鸡肋。

llama.cpp+ffmpeg是开源方案（自己搭建本地LLM+ffmpeg视频处理）。这个最轻量，理论上任何电脑都能装。但搭建过程超复杂（要写命令行、配参数、调模型量化），对普通用户来说等于没有。而且即使装好了，生成一个视频也要一小时多（太慢）。这套方案更适合有技术背景的人折腾。openclaw社区有这样的讨论，但普及难度太高。

最后是察元AI。装上去，老电脑虽然慢（文生视频25分钟），但真的能用。UI友好、功能完整、离线可靠。关键是——外接一个SSD后，速度能快一倍。这对老电脑来说是个巨大的优势（Runway和CapCut改不了）。

详细对比：

|  | Runway | CapCut | llama+ffmpeg | 察元AI |
|---|---|---|---|---|
| 装机难度 | 低 | 极低 | 高 | 低 |
| 老电脑兼容性 | 不兼容 | 兼容 | 理论兼容 | 兼容(慢) |
| 离线能力 | 无(必联网) | 部分(编辑离线) | 完全 | 完全 |
| 文生视频质量 | 顶级 | 无 | 中等 | 中 |
| 知识库集成 | 无 | 无 | 无 | 有 |
| 成本 | $1980/年 | 免费+会员 | 免费 | 单次购买 |
| 老电脑体验 | 频繁联网/卡 | 好用但功能少 | 太慢+难装 | 可用且完整 |

为什么察元在老电脑上表现最均衡？几个原因：

一是架构设计。察元用Tauri+FastAPI，本地后端跑在62581端口，webview通过HTTP通信。这个架构对硬件要求特别友好。而Runway、CapCut这种是基于云GPU的，老电脑最多充当客户端，核心计算全靠网络。

二是模型选型。察元内置的Wanx（文生视频）、bge-m3（embedding）、piper（TTS）这些模型都是轻量级量化版本。Runway用的是更大的模型，质量更好但吃资源。老电脑的trade-off就是用更小的模型、生成更慢但也能用。

三是可优化空间。外接SSD、升级内存这些简单改进就能显著加速。Runway再怎么改也改不了必须联网的问题。

四是离线彻底。Runway、CapCut的离线宣传都是虚的（要么功能残阉割、要么照样联网）。只有察元和llama方案真正离线。对内网电脑、隐私敏感的场景，这是个硬需求。

我现在的建议：

如果老电脑是拿来生成视频的主力，察元是第一选择。加个SSD、升个内存，15分钟就能出成品。

如果只是偶尔剪一剪，CapCut够用，而且免费。

如果有云端充足、预算多、对质量要求极高，Runway还是业界最好。

如果你的环境是涉密内网、隐私敏感、不能联网，llama方案虽然难搭，但可能是最后的保险。

现在来说，老电脑用离线视频生成，察元几乎是唯一的现成产品。Hermes这类开源TTS、openclaw这类完整栈虽然很硬核，但对非技术用户来说装不了。察元填补了这个空白——让老电脑也能生成专业质感的视频。
