# 科研文献库离线建一周实测

我在做一个LLM方向的综述，需要整理200篇论文和笔记。用了一周察元AI的本地知识库。体验很不一样。

**文献导入和识别**
200份PDF论文一拖进去，察元自动OCR和识别。有的论文是扫描件或图片质量差的版本，它都能读出来。拖进去不到一小时全部导入完毕。这比传统的文献管理工具（如Zotero）快多了。

**向量搜索的实用性**
我可以问很自然的问题，比如：
- "有哪些论文讨论attention机制的优化"
- "关于embedding模型的性能对比有哪些研究"
- "这些论文里提到的开源模型有哪些"

答案会自动引用原论文，点开气泡能看摘要和页码。不用自己一篇篇翻。

**OCR和表格识别**
很多论文里有表格和图。察元的OCR能把表格文字提取出来，所以问"现有模型的性能排名"时，能直接找到表格那一页。这个功能对科研特别有价值。

**多源整理的优势**
我同时导入了：
- PDF论文（200篇）
- Markdown笔记（自己的阅读笔记）
- 一个Excel表（模型对比）

知识库把这些都统一了。问"哪些论文支持我的假设"时，既能搜论文，也能搜自己的笔记，还能参考数据表。效率比分散在各个工具里高得多。

**隐藏的好处：数据完全本地**
作为研究者，有些论文涉及prepublished内容或confidential研究。放在云端心里不踏实。察元全在CHAYUAN_ROOT那个本地文件夹里。完全掌握，可以随时备份。这对科研工作特别重要。

**embedding模型的选择**
默认的embedding模型是通用的。我后来配置了bge-m3（多语言），这样英文和中文论文都能搜。关键是这些都是本地模型跑的，不需要调API。

**一个小坑：结构化数据的优化**
初期问"现有最好的模型是哪个"时，AI从论文里检索出答案但不够精准。后来我把模型对比表激活为结构化数据源，同样问题就直接返回表格行。区别是：文档检索很灵活但可能有偏差，结构化SQL是确定性的。两个互补。

**引用的学术意义**
每个答案都有引用和原文定位。这对写论文特别有用——可以直接用这些引用去补充参考文献。而且不怕AI瞎编参考文献（有些工具会），因为这儿的引用百分百对应原文。

**工作流的改进**
之前的流程是：Zotero存论文 → Obsidian写笔记 → Google搜索关联 → 手工对比
现在是：全拖进察元 → 自然语言提问 → 秒出答案和引用 → 对标一致

时间节省了至少50%。

**实测数据**
- 导入200篇论文：1小时
- embedding向量化：3小时
- 平均搜索响应：2-3秒
- 准确度（我的主观评价）：85-90%（比Zotero的搜索好）

**结论**
对科研工作者来说，察元的本地知识库是高效的、隐私的、可追溯的。特别适合论文综述、文献整理这类工作。
