# 网络版（服务版）按用户量收费 — 设计文档

- 日期：2026-06-20
- 状态：设计已评审通过，待写实施计划
- 范围：仅「网络版按用户量分级收费」。不含后台 NiceGUI→React 重构、联网 heartbeat、换绑、完整 5000-scaling 评估、按模块功能门控。

## 0. 背景与决策

察元双版本并行：单机版（desktop/Tauri，`platform-tauri`）与网络版（web，`apps/web`/`platform-web`）。本期为**网络版**新增一种收费模式：**按用户量分级授权**。

已敲定决策（brainstorming）：

1. **部署形态**：客户各自私有部署（单租户）。席位授权绑这套部署。
2. **计数对象**：总注册账号数，拦在 `create_user`（写路径），无并发语义。
3. **有效期**：按年订阅。席位令牌编码 maxUsers + 到期；到期回退默认 10（不删账号、仅不能再加）。
4. **校验方式**：离线令牌激活为主，可选联网校对。适配国产化/内网。
5. **默认上限**：开箱默认 10 用户；购买后升至 20/50/100/300/500/1000/3000/5000。
6. **实现路线（B）**：新增独立「部署授权」线，与现有 per-module count/time license **解耦**；复用现成 crypto/发码/扫码/后台管线。

**两条铁律（贯穿全设计）**：

- `is_single_machine()` 为真 → 整条 seat 逻辑短路，单机版执行路径一行不变。
- cap **fail-open**：无 profile + 无 license + 无配置 = 无限制。绝不「默认 10、单机豁免」（方向反了即定时炸弹）。

## 1. 总体架构：两半 + 一条契约

收费链路横跨 `/work/website`（Node，发码）与 `chayuan-server`（Python，校验），**契约 = 令牌 payload schema + Ed25519 公私钥配对**（沿用现有 license token 那套，不另造）。

```
[发码端] /work/website (Node)              [校验端] chayuan-server (Python)
 商品/定价(席位档)                           部署指纹 deployment_fp(首启生成)
 扫码支付 → 签发"部署授权"令牌(Ed25519) ─契约─► verify_token(离线) → 写 deployment_license.json
 (绑客户 deployment_fp + 年期)                → create_user 拦截 / seat-status API
                                             [前端] apps/web (React) 激活页+席位用量
```

## 2. 部署授权数据模型（与 module license 解耦）

独立命名空间，不碰 module license 的 entstore/redeemed.json。

> **载体决策（编码层约束）**：现有短码 `codec.py` 的 `kind` 字段仅 1 bit（只够 0=time/1=count）、`value` 仅 14 bit 单字段，装不下「maxUsers + 年期」两个数。故部署授权改用现成的 **Ed25519 令牌**（`token.py:verify_token` / website `token.js`，payload 任意 JSON、已跨仓兼容），管理员把令牌串粘进 apps/web 激活框（部署管理员场景，长串可接受）。短码体系仅留给单机 per-module license，不动。

授权落盘 `$CHAYUAN_ROOT/deployment_license.json`（新文件；单机根本不读）：

| 字段 | 含义 | 来源 |
|---|---|---|
| `maxUsers` | 10/20/50/100/300/500/1000/3000/5000 | 令牌 payload |
| `expireAt` | 年期到期时间 | payload.exp |
| `fp` | 绑定的部署指纹 | payload.fp（= 首启生成、购买上报） |
| `token` / `activatedAt` | 激活记录 | 激活时写 |

- 载体 = **Ed25519 签名令牌**，payload `{kind:'seat', maxUsers, fp, exp, durDays, oid, iat}`；server 直接从 payload 读 maxUsers（**无需 server 侧 tier 表**）。契约 = **payload schema（JSON）**，比短码位宽好同步。

## 3. 服务端：判定 → 拦截 → 暴露（chayuan-server）

### 3.1 部署指纹 deployment_fp

首启在 `$CHAYUAN_ROOT` 生成稳定随机 fp（存 `deployment_id.json`，随数据卷持久化）。激活页展示它，客户购买时上报（= 「报机器码换序列号」模式的服务器版）。

> 风险：容器重建若不挂持久卷会换 fp → 需重激活。**换绑/transfer 列为后续期。**

### 3.2 有效上限（唯一判定函数，fail-open）

```python
def effective_max_users() -> int | None:   # None = 无限制
    if is_single_machine():
        return None                          # 单机短路 (R1/R7)
    lic = read_deployment_license()
    if lic and not expired(lic):
        return lic.maxUsers                  # 已激活且未过期
    return DEFAULT_WEB_MAX_USERS             # = 10 (无 license/已过期回退, R3)
```

`is_single_machine()` 真实存在于 `chayuan/server/profiles/bootstrap.py`；打包桌面经 `sidecar.rs:360`(`--single-machine`)+`sidecar.rs:371`(`CHAYUAN_PROFILE=single-machine`)双保险设置，且 Tauri shell allowlist 钉死 sidecar 参数 → 对真·打包桌面可靠。

### 3.3 create_user 拦截（唯一写路径拦截点）

- 仅当 `effective_max_users() is not None` 时检查；`count(users) >= max` → 抛专用异常 `SeatLimitReached`（带 used/max/升级引导）。
- **计数口径（已定）**：`users` 表**总行数（含 admin）**。即「默认 10」= 1 个 admin + 至多 9 个其它。口径唯一，避免「哪种 role 算」的不一致。
  - 备选（未采用）：只数 `role='user'` 使 admin 不占名额，为 `filter(role='user')` 一行之差。如后续要改，全局计数点须同步。
- **绝不**在 login / session / 鉴权中间件加检查（R3：存量超额部署回退 10 时不能锁人在门外）。

### 3.4 并发安全（TOCTOU）

count→insert 放**同一事务**；Postgres 用基于常量 key 的 `pg_advisory_xact_lock` 串行化「建用户」临界区（建用户低频，开销可忽略）。避免「两请求都读到 9 → 都插入 → 变 11」。

### 3.5 REST API（React 消费，不碰 NiceGUI）

- `GET /api/v1/license/deployment/status` → `{ edition, maxUsers|null, usedUsers, available, expireAt, fingerprint }`（单机返回 `maxUsers:null` = 无限制）。
- `POST /api/v1/license/deployment/activate` `{ token }` → `verify_token`（Ed25519，内嵌公钥）+ 校 `payload.fp == deployment_fp` + `exp` 未过期 → 写 license → `{ ok, maxUsers, expireAt }`。
- 两端点在 `is_single_machine()` 时短路（status 返回无限制、activate 返回 not-applicable）。

## 4. 发码端：网络版商品 + 席位令牌（/work/website）

| 改动 | 文件 | 内容 |
|---|---|---|
| 商品类目 | `data/products.json` / `products.js` | 新增「网络版」产品 |
| 席位档位 | `data/license-pricing.json` / `pricing.js` | `kind='seat'` 档，带 `maxUsers` + 年价(20…5000) |
| 令牌签发 | `license/token.js` | Ed25519 签 seat payload `{kind:'seat', maxUsers, fp, exp, durDays, oid, iat}`；绑客户上报的 `deployment_fp`。**不改 codec/shortcode**（短码 kind 仅 1bit，塞不下） |
| 签发编排 | `payment/issue.js` `fulfill.js` | seat 订单行 → 按客户上报 fp 签部署令牌 |
| 下单 | 购买流程 | 表单收集 **deployment_fp**（类似机器码），而非 device mid |
| 后台 | `pricing-admin-routes.js` | 席位档管理(maxUsers 字段) |

> **跨仓契约（重点）**：契约 = **令牌 payload schema（JSON）** —— website `token.js` 签、server `verify_token` 验，二者已跨仓兼容（只需公私钥配对）。比短码位宽好同步，但 payload 字段名/语义仍须 website 与 server **成对改、成对测**。

## 5. 前端 apps/web（React，全部 isWeb() 门控）

- **部署授权页**：显示 deployment_fp（供购买）、当前 maxUsers/used/到期、粘贴令牌 → 调 activate。
- **用户管理**：顶部「X/N 席位」用量；达上限禁用「新建用户」+「升级席位」CTA（数据来自 `deployment/status`，不前端兜底判断）。
- 单机版（`isDesktop()`）这些 UI **完全不渲染**，用户管理保持无限制。

## 6. 约束与不变量（验收项）

1. 单机零影响：`is_single_machine()` 全程短路，desktop 执行路径一行不变。(R1)
2. cap fail-open：无 profile + 无 license + 无配置 = 无限制。(R1/R7)
3. 只拦 create_user，login/每请求零改动。(R3)
4. 计数口径全局唯一（§3.3）。(R2)
5. 并发用事务 + advisory lock。(R4)
6. 部署 license 独立命名空间，单机不读。(R5)
7. seat UI 全 `isWeb()` 门控。(R6)
8. NiceGUI 配置面板不加新功能（见 memory: 后台 React 重构延后期）。

### 风险登记（来自上线前审计）

R1 fail-open 方向、R2 create_user 误伤首启/存量/测试、R3 拦截点只拦新增不拦登录、R4 TOCTOU、R5 部署 license 与 module license 串味、R6 前端门控、R7 dev 模式 desktop 判定空档。本设计 §3/§5/§6 已逐条对冲。

## 7. 高并发姿态（本期范围）

席位检查是**低频写路径**（建用户一次，结果可缓存），不在任何热路径——「总注册数」口径正好避开 per-request 计数。网络版扑 5000 人的真正承载力（Postgres 连接池/Redis/Celery/Milvus/限流）由 **prod profile 既有配置**承担；**完整 5000-scaling 评估为单独交付**，不在本文档内。

## 8. 向后兼容 / 迁移

- 单机：零改动、无迁移。
- 存量网络部署：升级后无 license → 默认 10；**已有账号照常登录**，仅新建受限；给清晰「如何激活」提示。
- 无 DB schema 变更（users 表不加列；`deployment_license.json` 为新文件）。

## 9. 测试

- website(vitest)：seat 令牌签发(token.js)、payload 字段正确性。
- server(pytest)：`effective_max_users` 四态（单机 / 默认10 / 有效 license / 过期回退10）；create_user 拦截（限下放行、达限拒绝、**login 永不拒**）；TOCTOU 并发；edition 门控。
- 契约：activate/status 端点；website 签的令牌 server `verify_token` 能验通（同一公私钥）。
