# 后台控制台全量对齐原版（NiceGUI config_panel → React AdminConsole）— 主设计 Spec

- 日期：2026-06-21
- 状态：设计确认（用户已批准路线图与三项元决策），作为 S0–S6 各子项目的共同基准
- 范围：把原 8502 NiceGUI `config_panel`（64 文件 / ~44K 行 / 15 导航域 + 5 yaml 配置域）**全量迁移并重设计**到 chayuan-client React 独立管理控制台（`/admin`）。

> 本文是「主 spec」。已有的逐域设计文档（用户管理/MCP/工具/自定义工具）与 `2026-06-21-admin-config-domains-plan.md`（P1–P7：默认模型/模型平台/Redis/MinIO/DB/服务框架/数据目录）是本路线图的一部分，已完成项不重做。本文补齐它们**未覆盖**的域，并定义统一架构。

## 0. 元决策（brainstorming 已确认）

1. **总范围**：全量对齐原版（不止用户汇总的 16 条，含分词器/切分、向量库、知识库管理、配置向导、安装向导、可扩展性、服务拓扑、健康检查等整域）。
2. **双版本**：单机 desktop + 网络 web **共用同一套 React 后台**，按终端能力门控（沿用 `isWeb()` + 终端能力矩阵，避免做崩另一版）。
3. **首批**：基础配置域 `basic_settings` 全套。
4. **执行**：用户要求「一次性全部完成」——按 S0→S6 依赖顺序**连续实现、按子项目提交**，中途不停下逐项等审；每子项目完成即汇报。
5. **铁律**：不搞崩单机。NiceGUI 各页留到对应 React 域达 parity 才删；React admin 走主应用 admin JWT，不动 config_panel 其余页的密码门。

## 1. 统一架构

### 1.1 Schema 驱动的配置表单引擎（核心复用点，S0）

原版 5 个 yaml 配置域（basic/kb/model/tool/prompt）的字段元数据**已存在单一真源**：`config_panel/schema.py` 的 `ALL_SCHEMAS`（`FileSchema → Section → Field`，含 path/label/widget/help/needs_restart/choices/min/max/step/password 等）。

**决策：后端把 `schema.py` 以 JSON 暴露给前端，前端做通用「Schema→表单」渲染器。**

- 后端新增通用配置路由（admin-only）：
  - `GET /api/v1/admin/config/{file}/schema` —— 返回该 yaml 的 schema（sections/fields，JSON 化 `FileSchema`）。
  - `GET /api/v1/admin/config/{file}/values` —— 返回当前各 path 的值（敏感字段脱敏，附 `masked: true`）。
  - `POST /api/v1/admin/config/{file}` —— 按 path 写回（复用 `yaml_store.save_updates`，保留 ruamel 注释、原子写 + bak），返回 `needs_restart` 汇总。
  - `{file}` 白名单：`basic_settings|kb_settings|model_settings|tool_settings|prompt_settings`。
- 前端 `features/admin/config/` 新增 `<SchemaForm file=...>`：按 section 分块卡，按 widget 渲染（switch/number/text/password+toggle/textarea/select/yaml），脏值跟踪、保存、`needs_restart` 横幅、敏感字段 reveal。
- **收益**：basic/kb/model/tool/prompt 五域字段级配置一次引擎全覆盖，后续加字段只改 `schema.py`，前端零改动（最小漂移）。

### 1.2 终端能力门控

沿用 `isWeb()` 与「终端能力矩阵」记忆：网络版无本地原生能力（模型管理、数据目录写 rc、本机服务发现等）按域/按钮门控并给提示；单机版无浏览器专属能力的项同理。门控只隐藏/禁用 + 提示，不删功能。

### 1.3 后台壳（S0）

- 左侧菜单**分组可折叠**（折叠到 icon-only + 记忆展开态，localStorage），顶部加搜索/快速定位（#1）。
- 信息架构按「配置 / 内容 / 运维 / 监控 / 部署」重排。
- 统一弹窗基础设施（已有 ConfirmRoot/PromptRoot/ErrorDialogRoot），统一「分块卡 + 弹窗编辑」范式（#6/#15）。
- 隐藏 WS 端点（#8）与系统服务 api config（#9）：从主菜单移除/收进高级；端口（52581/52582 等）服务端固定，只读展示不提供改。

## 2. 子项目分解（S0–S6）

### S0 后台壳 + Schema 表单引擎
- 菜单折叠/搜索/重排（#1）；终端能力门控框架；§1.1 通用配置后端 + `<SchemaForm>`；统一弹窗/分块卡；隐藏 WS（#8）/api config（#9）。
- 后端：新增 `config_routes.py`（schema/values/save）。前端：`features/admin/config/`。

### S1 基础配置域 basic_settings（首批）
- 用 `<SchemaForm file="basic_settings">` 一次渲染全部 section：运行时、服务器绑定（端口只读/受限）、性能可扩展性（worker/DB 池/限流）、可观测性（JSON 日志/Prometheus/OTEL/**Langfuse 配置 + 连通检测 #12**）、多用户鉴权（JWT/默认管理员/自助注册）、异步入库（Arq 队列）、语义缓存。
- 额外：Langfuse 区加「检测」按钮 → 复用 `/admin/health`（Langfuse 自检）。
- 统一分块页范式即 #15 的样板。

### S2 知识库配置域
- `<SchemaForm file="kb_settings">`：**分词器 TEXT_SPLITTER_NAME（6 选 1）**、CHUNK_SIZE/OVERLAP、TOP_K/SCORE_THRESHOLD、缓存向量库数、中文标题增强、默认 KB/搜索引擎。
- 向量库配置（vs_config 7 种：faiss/milvus/zilliz/pg/relyt/es/chromadb）：类型选择 + 动态字段 + 连接测试 + 写 `DEFAULT_VS_TYPE`/`kbs_config`。后端补 `/api/v1/admin/vectorstore/{status,test,save}`。
- 知识库管理（kb_manage）：KB CRUD + 上传 + 分片查看/编辑/删除 + 检索测试 + 重建向量库 + 孤儿清理。后端复用已有 kb_routes，缺口补 HTTP。**网络版/单机版均可（走后端）**。

### S3 模型与工具配置补全
- 默认模型修复（#5：候选空→引导去模型平台；持久化链路核查）+ 采样参数（model_settings：HISTORY_LEN/MAX_TOKENS/TEMPERATURE 走 SchemaForm）。
- 模型平台复用前端（#5/#7）+ 工具参数/密钥（tool_settings 走 SchemaForm）+ 自定义工具（已有计划，补测试端点）。
- prompt 本地模板（#14：prompt_settings.yaml RAG 模板 + 原始 YAML 编辑）；React「Prompt」tab 拆成「Langfuse Prompts（监控）」与「本地 Prompt 模板（配置）」两入口，Langfuse 不可达时本地模板仍可用。

### S4 运维域
- 服务拓扑图（#11）：Client→Nginx→(API/WebUI/Panel)→(Redis/DB/Milvus) SVG + stroke-dasharray 流光动画 + 节点状态色 + 点击配置；React 用 SVG/Canvas 复刻。
- 本机服务发现（local_service_detector/catalog）：扫端口 + 协议握手 + 绑定到配置点；**仅单机版**（网络版门控提示）。后端补 `/api/v1/admin/discovery/*`。
- 注册检测：弹窗添加外部端点（复用已有 external + probe）+ 拓扑上显示连线。
- 服务配置向导（service_config）：先决条件六服务探活 + 就绪条 + 内联修复。
- 健康检查（health/service_checks）：六分类诊断 + 一键修复器；后端补 `/api/v1/admin/health/*`。

### S5 安装/模型生命周期 + vendor 编排（#10）
- 安装向导（install_dialog/recipes/task_manager）：向导式装 FunASR/CosyVoice/VoxCPM/OCR/Ollama/vLLM/ComfyUI，多镜像源、日志轮询、关闭不杀进程；后端补 `/api/v1/admin/install/*`（任务式）。**仅单机版**。
- 图像模型管理（image_model_panel）：下载/上传/smoke test/启用/删除 + HF 镜像/代理。
- vendor 服务（llama-server/whisper-server/imagemagick）打进 docker 并在「系统服务」可见启动（#10）：docker compose 模板 + readiness 注册已有，补「拉起 + 状态可见」闭环。

### S6 诊断与洞察
- 可扩展性诊断（scalability，修复性能页 #13）：静态分析 yaml → 并发承载估算 + 修复建议；后端补 `/api/v1/admin/scalability`。
- 业务监控仪表板（monitoring）：问答量/反馈分/KB 热度 时序+分布+7×24 热力（echarts，与用户管理域共用图表层）。

### 横切
- 用户/角色按模块分配（#2）：角色表 + 模块权限矩阵；后端补 role/permission。CreateUser 改弹窗（已部分）。
- KB 授权增强（#3）：查看全部人 KB + 每库 CRUD + 权限分配（已有 kb-acl，补「查看全部 + 更细粒度」）。
- 部署授权对齐客户端短码（#16）：与客户端授权码一致 + 扫码购买获取，短码。复用 reference_license_serial_system。

## 3. 验证
- 前端：`node_modules/.bin/tsc -p packages/app/tsconfig.json --noEmit`（每子项目）。触达文件 eslint。
- 后端：py312 `pytest` 相关单测 + `py_compile`；新路由补 schema/权限/敏感操作（强确认+admin+审计）测试。
- 真效果需重建 desktop sidecar / docker 镜像，提醒用户重建+重启。

## 4. 风险与边界
- 后端多个域当前**无 HTTP 路由**（kb_manage/vs_config/discovery/health/install/scalability/monitoring 直接调 Python），需新建路由层——这是工作量大头。
- 敏感写操作（DB create、存储迁移、安装、清空 Redis）一律强确认 + admin + 审计 + 需重启提示。
- 不在查询阶段接受外部 embedding model 参数；端口服务端固定。
- 逐域删 NiceGUI 仅在该域 React 达 parity 后。
