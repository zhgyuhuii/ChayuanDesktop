# 数字人套件 全方位优化方案(界面 / 布局 / 实用 / 性能)

> 状态:design。范围 = 数字人产品簇 3 个界面(**不含**时间轴视频编辑器,用户 2026-05-31 指定排除)。
> 决策已定:实时数字人页采用**直播间型(OBS)布局**;执行顺序 **①音色克隆 P2/P3 → ②RT 页打磨 → ③RT 真媒体管线**。

## 0. 背景与目标

数字人套件含 3 个界面:② 实时数字人页(`LiveAvatarPage`)、③ 数字人主页+生成(`DigitalHumanPage`/`PresetList`/`GeneratePanel`)、④ 音色克隆(`VoicePicker`)。目标:参考经典产品(HeyGen / 即梦 / 豆包通话 / OBS 直播间 / 剪映音色),把每个界面做到「布局稳、信息密度合理、交互可预期、无性能卡顿」。

**现状盘点(基于真实代码):**
- `LiveAvatarPage.tsx`(586 行):**全程 inline style**,与全项目 Tailwind `var(--cy-*)` 体系双轨;配置栏 flex-wrap 窄屏挤成多行;上下两段无比例约束;形象区静态 `<img>`/`<video>`,无沉浸感。
- `DigitalHumanPage.tsx`(37 行):极简 tab,信息密度低,无缩略图墙/状态概览。
- `VoicePicker.tsx`(342 行):上传/录音/列表/试听全堆在一个 popover,无质量反馈、无重命名。

## 1. 贯穿三界面的优化原则(经典产品共性)

1. **性能瓶颈优先**:先除卡顿再谈美观。热点 = 大列表无虚拟化、音频/视频解码阻塞主线程、巨组件全量重渲染、轮询无节流。
2. **布局一致性**:统一用 Tailwind `var(--cy-*)` token,消除 inline style 双轨;统一圆角/间距/控件高度(32px 控件、8px gap)。
3. **信息分层**:主操作显著、次操作收纳、危险操作二次确认;空态有引导。
4. **可预期交互**:加载有 skeleton、失败有重试、长任务有进度、不可逆有确认(复用 `confirmDialog`/`promptDialog`)。

## 2. 界面 ②:实时数字人页 —— 直播间型(OBS)布局

**骨架(用户选定):** 数字人全屏大背景;配置与对话作半透明浮层叠加其上;底部输入条。

```
+------------------------------------------------+
|  [全屏数字人舞台:<video>/idle 形象,object-cover]  |
|   +-------------+                +-----------+   |
|   | 配置浮层(可折叠)|                | 对话浮层    |   |
|   | 数字人▾/模型▾  |                | 回答流滚动  |   |
|   | 知识库▾/人设   |                | (半透明卡)  |   |
|   | 实时口型 ◉    |                +-----------+   |
|   +-------------+                                |
|                                                  |
|   [🎙说话] [____输入问题____________] [发送]       |
+------------------------------------------------+
```

**关键设计:**
- **舞台层**:`position:absolute inset-0`,`<video>`/形象 `object-fit:cover` 铺满;无形象时放渐变 + idle 动效(呼吸光晕),避免"白板"。
- **浮层可访问性**(化解 OBS 型遮挡缺点):浮层半透明 `bg-black/35 backdrop-blur` + 白字高对比;**配置浮层默认折叠成单条胶囊,点开才展开**,不长期遮画面;对话浮层可一键隐藏(沉浸观看)。
- **inline style 全量迁移到 Tailwind `var(--cy-*)`**,与全项目统一;暗色舞台上文字用固定高对比色(不跟随主题反色)。
- **比例约束**:舞台占满;输入条固定底部 `h-14`;浮层 `max-w` 限宽不糊整屏。
- **状态可见**:busy「思考中」骨架点、TTS 播放指示、实时口型连接态(连接中/已连/未起运行时)。
- **性能**:回答流 `setAnswer` 已是字符串增量,保留;TTS 队列已顺序播;舞台 `<video>` 用 `playsInline muted`;浮层用 `transform`/`opacity` 动画走合成层不触发 reflow。

## 3. 界面 ④:音色克隆 —— 功能(P2/P3)+ 布局打磨

**功能**(详见 `2026-05-31-voice-clone-p2-p3.md` 计划):P2 重命名 + 样本质量探测(过短/过长提示);P3 CosyVoice2 零样本高质量引擎(可验证骨架,真合成 [VERIFY])。

**布局打磨(参考剪映/即梦音色管理):**
- popover 内分区:**① 引擎/质量开关条 → ② 录音/上传主操作 → ③「我的音色」列表(每项:名称 + 试听 + 重命名 + 删除)**,纵向分组不再挤一行。
- 录音态用红点 + 秒数;上传后若有质量 warning 用提示条(非弹窗打断)。
- 列表项 hover 才出操作按钮,默认干净。

## 4. 界面 ③:数字人主页+生成 —— 缩略图墙 + 状态概览(参考 HeyGen/即梦管理台)

> 不在用户给的 ①②③ 执行序内,作为**后续波次**,本方案先记录设计,实施排在 RT 媒体之后或按需。

- 「我的数字人」从纯列表 → **缩略图卡片墙**(形象缩略图 + 名称 + 音色标签 + 「实时对话/生成」快捷入口)。
- 顶部状态概览条:数字人数量、进行中生成任务数。
- 生成 tab:表单分步骤化(选形象 → 选音色/引擎 → 旁白/商品图 → 生成),复用既有 `GeneratePanel` 控件不重写。

## 5. 执行顺序与可验证性(用户指定)

| 波次 | 内容 | 可验证性 |
|---|---|---|
| **① 音色克隆 P2/P3** | 重命名 + 质量探测 + CosyVoice2 引擎骨架 + VoicePicker 布局打磨 | ✅ 本机可验(真合成 [VERIFY]) |
| **② RT 页打磨** | LiveAvatarPage → OBS 直播间布局 + inline→Tailwind + 浮层可折叠/可访问性 + 状态可见 | ✅ 本机可验(typecheck;麦克风/视频 [VERIFY]) |
| **③ RT 真媒体管线** | 接 RT-P2 的 [GPU-VERIFY] 核心:MuseTalk 连续帧→aiortc track + TTS 推流 + 文字→LLM→TTS→口型编排 | ❌ best-effort,需用户 GPU+aiortc 环境 |
| ④ 数字人主页(后续) | 缩略图墙 + 状态概览 | ✅ 本机可验 |

## 6. 风险与红线

- RT 页 OBS 布局**不破坏** RT-P1/P2/P3 既有逻辑(send/TTS/WebRTC/麦克风),只重构呈现层。
- 音色克隆**不回归** P1 上传/录音/删除;engine 缺省 voxcpm。
- 性能改动以"不引入新依赖、复用既有 hook"为准。
- ③ RT 真媒体本机不可验,产物标 [GPU-VERIFY],诚实交付骨架供用户迭代。
