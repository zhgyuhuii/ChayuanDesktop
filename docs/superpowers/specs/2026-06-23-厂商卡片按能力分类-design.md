# 厂商卡片按能力分类显示(复用对话窗口分类体系)

- 日期:2026-06-23
- 状态:设计已确认,待写实施 plan
- 范围:`chayuan-client`(纯前端,零后端改动)

## 背景与问题

后台「模型厂商」页(`MarketplacePage` + `ProviderCard` 卡片网格)**没有按能力类型分类显示**:
每张卡都堆出全部类型标签,页面顶部也没有「按能力过滤」的入口。用户希望像**对话窗口**那样,
能按 对话 / 视觉 / 文生图 / 图像编辑 / 文生视频 / 图生视频 / 语音合成 / 语音识别 等分类过滤。

调查发现代码里有**两套并行的能力分类体系**:

| | 对话窗口(参照真源) | 模型厂商卡片(待修) |
|---|---|---|
| 真源 | `composer/modelCapabilityChip.tsx` 的 `CAP_META` + `transport/modality-stream.ts` 的 `ModalityCapability` | `marketplace/lib/modelTypes.ts` 的 `ModelType` |
| 分类 key | chat/vl/t2i/image_edit/t2v/i2v/tts/asr/ocr/embedding/rerank | llm/embed/rerank/text2image/text2video/image2text/image2image/tts/asr |
| 标签 | 对话/视觉/文生图/**图像编辑**/文生视频/**图生视频**/… | …/图生图/**视频生成(文生图生不分)**/… |
| 分类方式 | 按模型名前缀推断 `inferCapability()`,回退后端 `model_type` | 按后端 `*_models` 数组字段 |

用户列的 8 个分类**恰好就是对话窗口那套 `CAP_META`**;`modelTypes.ts` 缺「图生视频(i2v)」、
把「图像编辑」叫「图生图」、文生/图生视频不分。直接原因还有:`MarketplacePage` **没接能力过滤 UI**、
没把 `activeCapability` 传进 `ProviderCard`。

## 方案选择

选 **方案 A:混合 —— 后端数组为权威来源 + 复用对话窗口分类体系(CAP_META/inferCapability/
CapabilityChip)+ 视频桶按模型名拆分,纯前端**。

放弃的备选:
- 方案 B(纯前端名字推断):会丢掉后端对 视觉/文生图 的权威判定(`gpt-4o` 被一律判「对话」),退化。
- 方案 C(后端加 `image2image_models`/`image2video_models` 字段打穿 6 层):数据模型最干净但跨
  chayuan-server、改动大,对「分类显示」属过度工程。本期不做,作为后续增强。

## 架构与改动

### 一、能力分类桥接(核心复用点)

新增 `marketplace/lib/capabilityGrouping.ts`,**真复用** composer 的 `inferCapability` /
`CAP_META` / `CapabilityChipMeta` / `listExistingCapabilities` 思路,不自造分类:

字段 → 后端 `model_type` 提示串,再喂给现成的
`inferCapability({ id: 模型名, model_type: 提示 })`:

| PlatformConfig 字段 | 喂入 model_type | 结果 capability |
|---|---|---|
| `llm_models` | `llm` | chat(对话) |
| `image2text_models` | `image2text` | vl(视觉) |
| `text2image_models` | `text2image` | t2i(文生图) |
| `image2image_models` | `image_edit` | image_edit(图像编辑) |
| `text2video_models` | `text2video` | t2v / **i2v(按模型名拆)** |
| `text2speech_models` | `text2speech` | tts(语音合成) |
| `speech2text_models` | `speech2text` | asr(语音识别) |
| `embed_models` | `embed` | embedding(嵌入) |
| `rerank_models` | `rerank` | rerank(重排) |

关键:`inferCapability` **先按模型名前缀判**(`wanx-i2v`→图生视频、`qwen-image-edit`→图像编辑),
名字判不出**才回退**字段提示。于是:
- `gpt-4o` 在 `image2text_models` → 名字判不出 → 回退 `image2text` → 视觉(**保住后端权威**);
- `wanx2.1-i2v-*` 在 `text2video_models` → 名字命中 → **图生视频**(自动拆分,无需后端字段);
- `qwen-image-edit` 无论后端放哪个数组 → 名字命中 → 图像编辑。

导出:
- `groupModelsByCapability(platform, { excludeDisabled }): { cap, meta: CapabilityChipMeta, models: string[] }[]`
  —— 按 `CAP_META` 顺序,扣除 `disabled_models`,空桶可选过滤。
- `listPlatformsCapabilities(platforms): CapabilityChipMeta[]` —— 页面级动态 present(跨所有厂商)。

### 二、ProviderCard 显示层改造

- `activeCapability` prop 词表:`CapabilityKey(=CAPABILITY_ANY | ModelType)` → `ModalityCapability | typeof CAPABILITY_ANY`。
- `buildGroups` 改用 `groupModelsByCapability`(替掉 `groupModelsByType`)。
- `TypeTagDropdown` 触发器改用 **CAP_META 的 Tailwind 配色 + label**(与对话窗口同色同名);
  下拉列模型、点选回调 `onSelectModel` 逻辑不变。
- 其余(左侧状态色条 / 状态徽 / tags 徽 / CTA 文案 / logo / ⚙️ 设置入口 / 安装指南)**全不动**。

### 三、MarketplacePage 顶部分类过滤条(对照对话窗口)

- 在现有「分类 tab(推荐/全部/本地/国内/国外/聚合/自定义)+ 搜索框」下方,新增**能力 chip 行**:
  复用 `CapabilityChip` + 一个「全部」按钮,样式照 `ModelMenuList.tsx:395-441`(吸顶、rounded-full chip)。
- chip 集合 = `listPlatformsCapabilities(按现有 tab/搜索过滤后的列表)`,**动态 present**;≥2 类才显示该行。
- 新增 `activeCapability` 页面 state(默认 `CAPABILITY_ANY`)。过滤链追加一道:
  选中某能力 → 只留「含该能力模型」的厂商,并把 `activeCapability` 透传给每张 `ProviderCard`(卡内只显示该类模型)。
- 切「分类 tab / 搜索」时若当前 `activeCapability` 不再 present,回落 `CAPABILITY_ANY`。

## 边界 / 取舍 / 已知缺口

- **图像编辑数据缺口**:厂商目录 `ProviderCatalogEntry` 无 `image2image` 字段,
  `catalogEntryToPlatformConfig` 把 `image2image_models` 硬编码 `[]`。靠模型名推断兜底
  (名字含 `*-image-edit` 能正确归类);若某图像编辑模型名字不可识别且后端无该字段,该能力不显示
  —— 动态 present 下即「不出这个 chip」。彻底补全走方案 C(后续)。
- **i18n**:能力标签直接用 `CAP_META` 的中文(与对话窗口一致),不走 `modelMarket.capability.*` i18n。
  换取全 app 一套标签;代价是这几个 chip 暂无英文(后续要英文在 `CAP_META` 补)。
- **`modelTypes.ts` 保留**:它被模型配置编辑器(`PlatformSettingsDialog` / `ModelTypeAccordion` /
  `ModelLineEditor`)依赖(类型↔字段映射),编辑流程不动、零影响。本设计只替换**显示/过滤**分类。

## 影响范围(blast radius)

- 新增:`marketplace/lib/capabilityGrouping.ts`。
- 改:`marketplace/components/ProviderCard.tsx`、`marketplace/MarketplacePage.tsx`。
- 不动:`marketplace/lib/modelTypes.ts` 及其编辑器消费方。
- 待核:`modelGallery/ModelHubRow.tsx` 也 import 了 `ProviderCard`,实现时确认它是否传 `activeCapability`
  / 受词表变更影响(大概率不传,默认 ANY 不受影响)。

## 验证

- 前端 typecheck:`node_modules/.bin/tsc -p packages/app/tsconfig.json --noEmit`(本机 admin 可跑)。
- 真机:厂商页出现能力过滤条;选「图生视频」只剩有 i2v 模型的厂商且卡内只显该类;
  「图像编辑」对 `qwen-image-edit` 正确归类;默认 ANY 时行为同现状。

## 不做(YAGNI)

- 不动后端、不加 `image2image_models`/`image2video_models` 字段(方案 C)。
- 不改对话窗口、不改 `modelGallery` 的 hub 词表。
- 不做能力分类的英文 i18n(等有需要再补 CAP_META)。
