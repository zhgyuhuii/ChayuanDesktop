# 统一文件下载/预览 — Design

日期: 2026-06-25
范围: chayuan-server(后端统一文件端点 + adapter) + chayuan-client(前端统一解析层)
目标: 把 6 类文件来源(KB文档/图片源/模态产物/引用/数字人DH/视频生成VG)的下载、预览
      统一到「一个后端端点 + 一套前端解析」,消除各处零散实现(window.open 等)。

## 背景与问题

现状各处下载/预览实现不一致,且后端存储/端点分裂:
- 后端: KB文档/图片源/模态artifact 已接 file_storage(同源stream+回填,minio可用);
  DH全系列、VG模块纯本地 FileResponse(单容器+持久卷可用,多副本404);
  端点散落 /knowledge_base/download_doc·preview_doc、/v1/artifacts、/digital-human/.../file、
  /video-generation/.../file、/knowledge_source/{id}/image。
- 前端: 下载有的 window.open(KbResultsView,刚因 nginx 整页导航被 SPA fallback 吞而出 bug)、
  有的 downloadUrlAsFile(fetch blob);预览有的 PreviewPanel、有的直接 <img/video src>。
- 每加一种文件就要改 nginx 反代白名单 + token 中间件白名单。

## 决策(已与用户逐节确认)

方案 1:**统一文件端点 + adapter 分发**(对齐项目已有 retrieval.query 的 refs/adapters/results 分层)。
- 后端一个端点 `/v1/files`,按 kind dispatch 到各来源 adapter(权限/定位/stream 各自封装,复用现有逻辑)。
- 前端一套 FileRef + resolveFileUrl/downloadFile/openFilePreview,各处下载/预览全接;下载统一 fetch blob。
- 旧端点保留转薄壳,WPS/历史链接/dl_token 零破坏。
- DH/VG 产物接 file_storage(照搬 artifacts:本地权威+镜像minio+回填),为多副本铺路(单容器可延后)。

## 1. 统一文件端点 + ref 协议 + 白名单

端点(query-based,单一前缀便于白名单):
```
GET /v1/files?kind=<k>&<定位参数...>&token=<jwt>&download=<0|1>
  kb-doc      kb=&file=
  image       source_id=&image_id=
  artifact    name=<sha.ext>
  dh-task     task_id=
  dh-avatar   ref=<bundled:|user:>
  dh-product  ref=
  vg-task     task_id=&file=
  vg-material material_id=
  vg-bgm      name=
```
- 选 query 而非 path:参数多/含中文文件名好编码;只需把 `/v1/files` 一条前缀加进两个白名单。
- nginx: `/v1/files` 加进 `@route` 的 `$spa=0` 列表(整页导航/iframe 也反代后端,不被 SPA fallback 吞)。
- token 中间件: `/v1/files` 加进 `auth/middleware._QUERY_TOKEN_ALLOWED_PATHS`(浏览器 img/iframe 靠 query token)。
- `download=1` → Content-Disposition: attachment;否则 inline(预览)。

## 2. adapter 接口 + 各来源 adapter + 统一结果

统一结果(results):
```python
@dataclass
class FileBlob:
    open_stream: Callable[[], BinaryIO]   # 惰性打开:本地句柄 / minio stream / bytes
    media_type: str
    filename: str
    size: Optional[int] = None            # 有则支持 Range(视频拖动)
    cache: str = "private, max-age=0"     # artifact=immutable 1y;其余 private
```

adapter 接口(每来源一个,职责单一可独测):
```python
class FileAdapter(Protocol):
    kind: str
    def authz(self, user, params: dict) -> None: ...           # 失败抛 HTTPException(401/403)
    def locate(self, params: dict, *, preview: bool) -> FileBlob: ...
```

5 个 adapter(封装现有逻辑,不重写):
| adapter | authz | locate 来源 | 预览特殊处理 |
|---|---|---|---|
| kb-doc | _require_read(user,kb) / dl_token | NS.KB_CONTENT(已同源stream+回填) | office/pdf 走现有 download_doc(preview=True) |
| image | KB ACL(image source) | NS.IMAGE_FILES(已stream+copy_to_local) | 直接 |
| artifact | require_auth_enabled(登录即可) + sha 内容寻址隐蔽 | NS.ARTIFACTS + fetch_from_storage 回填 | 直接 |
| dh | task owner / avatar 公开 | 现本地 result_path/resolve_avatar_path(阶段4接file_storage) | 直接 |
| vg | task owner / material owner | 现本地 task_dir/storage_dir(阶段4接file_storage) | 直接 |

路由层(薄): `file_router` 只做 kind→adapter 查表 + authz() + locate() → 包成 StreamingResponse/FileResponse
(带 Range/Cache/Disposition)。不在路由堆业务(对齐 CLAUDE.md:路由只协议适配)。权限按来源各自处理。

## 3. 前端统一解析层

FileRef(discriminated union,前端唯一文件描述):
```ts
type FileRef =
  | { kind: 'kb-doc';   kb: string; file: string }
  | { kind: 'image';    sourceId: string; imageId: string }
  | { kind: 'artifact'; name: string }
  | { kind: 'dh';       sub: 'task'|'avatar'|'product'; id: string }
  | { kind: 'vg';       sub: 'task'|'material'|'bgm'; id: string; file?: string };
```

三个统一函数(替换各处零散实现):
```ts
resolveFileUrl(ref: FileRef, opts?: {download?: boolean}): Promise<string>  // → /v1/files?...&token=
downloadFile(ref: FileRef, filename: string): Promise<void>                 // fetch blob→平台保存(复用 downloadUrlAsFile)
openFilePreview(ref: FileRef): void                                         // usePreviewStore.open + PreviewPanel
```

各处接入:
- KbResultsView 下载 window.open → downloadFile({kind:'kb-doc'})(根治 nginx 吞 + 不闪新标签)
- ImageCard/MessageActionPanel downloadUrlAsFile(artifact.url) → downloadFile({kind:'artifact'})
- VG/DH 各自 url helper → downloadFile({kind:'vg'/'dh'})
- 预览各处 → openFilePreview(ref) 统一 PreviewPanel
- useFileUrl 收敛为 resolveFileUrl 的薄封装;PreviewPanel 渲染器注册表不变,只换取 URL 来源。

## 4. 存储统一、兼容、分阶段、测试

存储统一(DH/VG 接 file_storage):
- 新增专用 NS DH_ARTIFACTS/VG_ARTIFACTS(不复用 ARTIFACTS,避免命名空间混淆);产物落盘本地权威+镜像minio(fail-open),
  下载本地优先+fetch_from_storage 回填,照搬 artifacts。
- 兼容旧数据:adapter.locate 先查本地旧路径(task_dir/result_path)命中即用,未命中再查 file_storage。存量零迁移。

向后兼容:旧端点(download_doc/preview_doc、v1/artifacts、digital-human/.../file、video-generation/.../file)
保留,内部转调对应 adapter(薄壳)。WPS、历史链接、已发 dl_token 继续可用。

分阶段(每阶段独立验证+提交):
1. 后端 file_router + adapter 框架 + kb-doc/image/artifact 三 adapter(已 file_storage,直接封装)
   + nginx/token 白名单加 /v1/files。
2. 前端 FileRef + resolveFileUrl/downloadFile/openFilePreview + PreviewPanel 收敛;
   KB/图片/artifact 各处下载预览切新端点(根治 window.open)。
3. 后端 dh/vg adapter(先读本地兼容) + 前端 DH/VG 下载预览切新端点。
4. 存储:DH/VG 产物接 file_storage(镜像+回填) — 多副本铺路(单容器可延后)。
5. 旧端点转薄壳转调 adapter(可选/长期并存)。
阶段 1-3 完成即达成「前端+后端统一解析」主目标。

测试:
- 后端:每 adapter authz/locate 单测(KB ACL 放行/拒绝、artifact 内容寻址、owner 校验);file_router dispatch;旧端点转薄壳回归。
- 前端:resolveFileUrl(各 kind 拼 URL+token)、downloadFile/openFilePreview 纯逻辑测;typecheck。
- nginx:/v1/files 整页导航反代(不被 SPA 吞)。

## 风险

- 中等:跨前后端 + 改多处调用点。靠「adapter 封装现有逻辑(不重写)+旧端点保留+分阶段」控制风险。
- 版本号一律走 scripts/bump-version.py(当前 2.0.311)。
