# 察元 构建 → 上传 → 下载 → 安装 全流程

本文覆盖三类应用的构建与一次完整发布:

- **离线安装包**:桌面产品本身(用户最终安装的东西),分 lite/standard/pro 三档、各平台一个。
- **上传端(发布客户端 / publisher)**:维护者用,登录后把离线包上传到 aidooo.com 并发布、生成在线清单。
- **下载端(安装器 / installer)**:用户用,按档从 aidooo.com 下载安装(或用户直接下离线包)。

> 三者关系:维护者本机**构建离线包** → 用**上传端**登录上传发布 → 用户用**下载端**按档下载,或直接下离线包安装。

---

## 0. 版本号规则(从 2.0.1 起,每次修改末位 +1)

版本号当前为 **2.0.1**。每次改动后 +1(2.0.1 → 2.0.2 → 2.0.3 …)。

版本号是**单一真源 + 3 个镜像**,构建脚本会一次性写全:

| 文件 | 作用 |
|---|---|
| `VERSION`(仓库根) | 真源 |
| `chayuan-client/apps/desktop/src-tauri/tauri.conf.json` | 决定离线包文件名里的版本 |
| `chayuan-client/apps/installer/src-tauri/tauri.conf.json` | 下载端版本 |
| `chayuan-client/apps/publisher/src-tauri/tauri.conf.json` | 上传端版本 |

**离线包文件名规约**(上传端据此自动识别,务必一致):

```
chayuan-<版本>-<平台>-<档位>.<后缀>
例:chayuan-2.0.1-win-x86_64-standard.msi
   chayuan-2.0.1-mac-arm64-pro.dmg
   chayuan-2.0.1-linux-x86_64-lite.AppImage
```

- 平台:`win-x86_64 | win-arm64 | mac-x86_64 | mac-arm64 | linux-x86_64 | linux-arm64`
- 档位:`lite | standard | pro`
- 后缀:`msi exe dmg deb AppImage tar.gz zip`(构建脚本会自动改成此规约名)

## 1. 一键构建(推荐)

脚本 `chayuan-client/scripts/release.mjs`(跨平台,Node 原生),会:**升版本 → 构建当前平台离线包 → 改名规约 → 构建上传端+下载端 → 全部收拢到 `release/<版本>/`**。

在 `chayuan-client/` 目录下运行(任选其一):

```bash
# Windows:双击 scripts\release.cmd,或命令行:
node scripts\release.mjs

# mac / Linux:
bash scripts/release.sh
# 或
node scripts/release.mjs
```

常用参数:

```bash
node scripts/release.mjs                 # 版本末位 +1 + 构建离线包(standard)+ 两个客户端
node scripts/release.mjs --set 2.0.5     # 指定版本号
node scripts/release.mjs --no-bump       # 不改版本,用当前版本构建
node scripts/release.mjs --tier pro      # 离线包档位 lite|standard|pro(默认 standard)
node scripts/release.mjs --offline-only  # 只构建离线包
node scripts/release.mjs --clients-only  # 只构建上传端+下载端
node scripts/release.mjs --version-only   # 只升/写版本号,不构建
```

**产物布局**(一个文件夹下,便于管理):

```
release/<版本>/
  offline/                                  ← 离线安装包(上传端要上传的)
    chayuan-2.0.1-win-x86_64-standard.msi
  clients/                                  ← 维护者用的上传端 + 用户用的下载端
    察元发布客户端_2.0.1_x64-setup.exe        ← 上传端(双击它登录上传)
    察元下载客户端_2.0.1_x64-setup.exe        ← 下载端(发给用户)
```

> **跨平台**:Tauri 不能跨系统打签名安装包。要 Windows 包就在 Windows 上跑脚本,要 mac 包就在 mac 上跑,Linux 同理。每个平台各跑一次,`offline/` 会各自多出该平台的包。

## 2. 手动分步(不想用脚本时)

### 2.1 构建离线安装包(桌面产品)

在 `chayuan-client/` 下,按档位:

```bash
# lite(轻量/纯云,不打模型也不打模型依赖)
pnpm --filter @chayuan/desktop build:thin

# standard(集成:除模型外全部打进去)/ pro 客户端构建相同
pnpm run build:desktop:full
```

产物在 `apps/desktop/src-tauri/target/release/bundle/`(Windows 为 `msi/` 下 `.msi`,Linux 为 `deb/`、`appimage/`,mac 为 `dmg/`)。

把产物**改名为规约名**并放进 `release/<版本>/offline/`,例如:

```
Chayuan_2.0.1_x64_en-US.msi  →  chayuan-2.0.1-win-x86_64-standard.msi
```

> **pro(全量·含模型)**:客户端构建与 standard 相同,差别在 **sidecar 要把模型权重一起打进去**——这是 `chayuan-server` 侧的打包步骤(见 `chayuan-server` 的 `PACKAGING.md` 与 `packaging/pyinstaller/build.py`,以及 `install-bundled-models`)。打出含模型的 sidecar 后再走上面的桌面构建,改名为 `...-pro.<后缀>`。

### 2.2 构建上传端(发布客户端 / publisher)

```bash
cd apps/publisher
pnpm tauri build
```

产物在 `apps/publisher/src-tauri/target/release/bundle/`(`察元发布客户端_<版本>_*.exe/.dmg/...`)。

### 2.3 构建下载端(安装器 / installer)

```bash
cd apps/installer
pnpm tauri build
```

产物在 `apps/installer/src-tauri/target/release/bundle/`。

把 2.2、2.3 的安装器都放进 `release/<版本>/clients/`。

## 3. 上传与发布(用上传端,图形操作)

1. **双击** `release/<版本>/clients/` 里的「察元发布客户端」。
2. **登录**:输入用户名 / 密码 / 验证码(图形验证码,点图可刷新)。
3. **检测**:填 git 仓路径(取版本与更新说明)和构建产物目录(指向 `release/<版本>/offline/`),点「检测」。
   - 会显示「本地版本 ↔ 线上版本」和一张「平台 × 档位」矩阵,自动勾选未发布的离线包。
   - 文件名不规约的会标「needsManual」,可就地手动补平台/档位。
4. **上传**:点「上传并发布勾选项」,每个包有进度条,支持断点续传。
5. **发布**:上传后自动发布(publish),离线包即对外可下载。
6. **生成在线清单**:点「生成并发布在线安装器清单」,合成 `installer-manifest.json` 并上传——**下载端**据它按档下载。

> 后端(aidooo.com / website)无需任何改动,上传端复用其现成的登录、验证码、分块上传、发布接口。

---

## 4. 用户下载与安装

两条路,任选:

- **下载端(在线安装器)**:把 `clients/` 里的「察元下载客户端」发给用户。用户运行 → 选档位(轻量/集成/全量)→ 它读在线清单、从 aidooo.com 按档下载并安装,带进度。不同平台自动下对应平台的包。
- **直接下离线包**:用户从 aidooo.com 直接下载 `offline/` 里对应平台对应档位的离线安装包,双击安装,**装时无需联网**。

---

## 5. 前置条件 / 排错

- **Rust 工具链**:构建任何 Tauri 应用(离线包/上传端/下载端)都需要 Rust(`rustup`)。
- **Windows 应用控制策略拦截(os error 4551 / 应用程序控制策略已阻止此文件)**:冷构建时 Smart App Control / WDAC 可能拦截 cargo 现编的未签名构建脚本与过程宏,导致 cssparser/anyhow 等报错。处理:关闭 Smart App Control,或给 `C:\Users\<你>\.cargo` 与项目 `target` 目录加杀软/受控文件夹访问排除项,再删 `target` 重新构建。
- **`pnpm` 未找到**:确保已 `corepack enable` 或全局装 pnpm。
- **node 版本**:脚本用 Node 原生 API(`fs.cp`、ESM),建议 Node ≥ 18(已在 Node 22 验证语法)。

## 6. 三档语义回顾

| 档位 | 含义 | 客户端构建 | 模型 |
|---|---|---|---|
| **lite 轻量** | 纯云,能运行即可,不打模型、不打模型依赖 | `build:thin` | 无,全部走外部模型 |
| **standard 集成** | 除模型外全部打进去 | `build:desktop:full` | 无权重,推理/服务依赖齐全 |
| **pro 全量** | standard + 模型权重一起打 | `build:desktop:full` + 含模型 sidecar | 有(chayuan-server 侧并入) |
